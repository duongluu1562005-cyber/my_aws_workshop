DATABASE AND INTEGRATIONS

Prepare application storage and PDF scanning before running the backend. Database consumes the networking from section 5.3. Integrations uses the Foundation media bucket and delivers scan results to the API worker.

This session provisions a Fresh database. Bootstrap, migrations and demo seeding run during Runtime setup after RDS creation completes.

5.4.1 — Create a Fresh Database

database.yaml defines three main resources and database access settings.

Resource or settingPurpose
DB subnet groupPlaces RDS in private DB subnets from Network.
PostgreSQL parameter groupEnables rds.force_ssl to require TLS.
RDS instanceStores Tindy data using PostgreSQL 17, db.t4g.micro and Single-AZ configuration.
RDS-managed master secretSupplies the administrative credential to the bootstrap task.
Deletion protection and snapshot policyProtect database deletion and request a snapshot under the template policy.

Use DBProvisionMode = Fresh, leave the snapshot identifier empty and enable deletion protection. RDS creates database tindy and master user tindy_admin. The API uses a separate DB credential prepared later.

Expected result is CREATE_COMPLETE and five Outputs covering endpoint, port, identifier, master secret ARN and provision mode. Schema preparation and demo data follow in section 5.5.

5.4.2 — Deploy Integrations

integrations.yaml configures PDF scan result delivery and operational notifications.

ComponentPurpose
GuardDuty Malware Protection planScans new objects under certificates/pdf/ and ai-input/pdf/ in the media bucket.
Tag scanned objectsRecords scan results on objects to support access controls.
EventBridge ruleDelivers scan result events to the queue.
SQS queue and policyReceive messages for the API worker.
Dead-letter queue and alarmRetain failed messages under the redrive policy and detect backlog.
SNS topic and email subscriptionSend alerts to the confirmed recipient.
Conditional ALB/API alarmsUse new ALB/target group dimensions after Runtime deployment.

Leave both ALB metric dimensions empty initially. After creation, confirm the SNS email subscription and verify the Active protection plan, tagging and both PDF prefixes.

Inputs and outputs

DependencyReferences
Network → DatabasePrivateDbSubnetIds, DatabaseSecurityGroupId.
Foundation → IntegrationsMediaBucketName.
Database → Runtime preparationDBEndpointAddress, DBMasterSecretArn, DBProvisionMode.
Integrations → RuntimeGuardDutyProtectionPlanArn, GuardDutyQueueUrl.
Runtime → Integrations updateNew ALB/target group metric dimensions for alarms.
